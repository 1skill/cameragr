**结论：这轮明显推进了上线准备，但还不能说“剩下都等用户”。** C8、C11 仍有值得现在修的正确性缺口；C9 尚未执行，C13 主要证明了适配代码存在。建议再做一轮有边界的收口，然后等真实联调，停止扩功能。

本次只读文档和代码，未修改文件、未重跑远程测试或真机验收；测试通过与部署状态沿用 PROGRESS 的记录。当前消息未见附图，不作视觉验收结论。

### 1. 六项最大的遗留风险

| 项目 | 判断与说满之处 |
|---|---|
| **C8 并发、账号隔离** | 领奖／兑换补了代次检查，但 `ClubPage.swift` 的 `post()`、`sendComment()`、`rename()`、`agreeToRules()` 仍有等待后直接写状态的路径；`open(postID:)` 也可能回填旧照片。**“所有异步写回都校验”不成立。** |
| **C10 弱网＋C9** | 保草稿、幂等和审核结果入口方向正确。但图片加载失败仍可能只剩暗块；403 重取失败缺少明确恢复动作。27 步清单是准备成果，不能替代响应丢失、换账号、真机重启验证。7／14 天正式日期验证应现在排期。 |
| **C6a 通知队列** | 租约能减少并发抢发，**不能保证不重复送达**：邮件发送成功、写回前进程中断，重试仍可能再发。“2／4／8 分钟退避”也是最早可重试时间；只有整点任务兜底时，实际可能等近一小时。八次失败后缺少清晰的人工补送闭环；真实送达仍待域名。 |
| **C11 恢复、日志** | **发现新的奖励恢复竞态：** `leave()` 先读取奖励写 R2 台账，随后才事务删号；期间若领取成功，当前 D1 的防重领记录完整，R2 台账却可能漏档。恢复到领取前，再重放删号，可能重新放出该档资格。另，“恢复 D1＋R2”写满了，实际是 **D1 回滚＋现存 R2 清理**，没有照片恢复。 |
| **C12 流量测算** | 是单次操作成本抽样，**不是并发容量验证**。未测真实照片分布、峰值、CPU 余量及完整 App 请求；“100 日活完全够用”应附假设。70% 告警还是建议，不是已生效保障。缩略图缓存不能直接当作确定节省比例。 |
| **C13 无障碍、五语** | 动态字号、朗读标签、缓存是实质改进；但不能据此称“VoiceOver 主链路完成”。投稿选图使用手势＋按钮特征，需验证朗读后的激活动作；还缺焦点顺序、关闭后焦点返回、键盘遮挡和最大字号证据。母语校对仍未完成。 |

另外两处文案应收紧：

- 删号提示“账号及所有内容已删除”，与异步清照片、保留防重领奖励哈希和删号台账不完全一致。
- `runbook-backup.md` 的“照片丢失只可能是误操作整个桶”过于绝对；权限、代码缺陷和局部误删也可能造成损失。**不重开已定的不备份照片方案，只如实说明恢复边界。**

### 2. 不等用户，现在做什么

| 优先级 | 具体提案、使用方式与完成标准 |
|---|---|
| **P0-1 账号隔离补齐** | 覆盖投稿、留言、改名、规则同意、打开照片的成功和失败回调；旧账号任务不得修改新账号状态、清新草稿或继续规则后的提交。**完成＝可控延迟下，A 请求未返回→退出→B 登录→A 返回，界面与本地状态仍属于 B。** |
| **P0-2 修恢复竞态** | 协调删号与领奖，确保恢复所依赖的外部记录不会漏掉已领取档位。**完成＝人为暂停在“台账已写、删号未提交”处并发领奖，再恢复到领取前、重放删号，仍不能重领。** 顺带验证维护期间管理员会话过期如何恢复操作；当前维护模式会挡 Apple 登录。 |
| **P0-3 通知故障收口** | 补发送后写回失败、租约到期、并发新增举报、八次失败测试。人工补送放在现有“我的→提醒”里，沿用现有纸张和文字位置。**完成＝失败可定位、可补送、不丢新增举报；重复邮件有可识别编号；文档写清实际重试节奏。** |
| **P1-1 弱网与无障碍证据** | 在现有照片背面／投稿纸内补明确的图片重试反馈，不加新页面；模拟器先跑五语、最大字号、VoiceOver 主路径。**完成＝能选图、提交、领取、取消删号并返回原位置；失败后有可操作出口。** 真机结果继续挂 C9。 |
| **P1-2 容量补测** | 用 App 实际导出图，补普通浏览、集中投稿、热点图片三组负载，记录 CPU、失败率、P95 和实际存储；给出 1 万日活费用区间。**完成＝容量建议有边界、触发条件及可执行降载步骤；未配置告警明确标待启用。** |
| **P1-3 完成 C14 成品草稿** | 做成逐份可审阅稿和字段表，只把必须由用户确认的字段留空，不能整项写“等用户”。 |

**我不同意继续铺新功能，也不同意现在停下。** 上述收口完成后，如果只剩描述文件、域名、用户决定和真机参与，就停工程推进；保持缺陷清单，等待联调。不要再拿新美术、Web 后台或奖励玩法填空档。
