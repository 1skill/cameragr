# Koco 社区与主题活动方案（草案 v0.1，2026-11-23）

用户已定：大陆以外先做（大陆搁置）；三种主题节奏同时跑；12 月先上 v1（不含社区），社区分三步在之后版本上线；只能发 Koco 拍的照片；连续打卡 3 天（任一主题）送一卷。活动设计由用户主导，技术方案我负责。

## 1. 活动模型
- 主题 Theme：id、类型（daily / weekly / festival）、开始结束时间（按用户所在时区的自然日）、标题（多语言）、一句题目、示范照片、推荐胶卷、可选限定胶卷（节日）。
- 同一时间可有：1 个每日小题 + 1 个每周大题 + 0–1 个节日主题。
- 打卡 Check-in：某天在任一主题放入一张当天用 Koco 拍的照片。连续天数按人算、跨主题（memory: check-in streak rule）。3 天送一卷；7 / 30 天的奖励待用户定。
- 小册：参加过的主题自动成册；现在的「它睡着了」小册（BookStore issue）是一本主题小册的雏形。
- 来信：可带上主题（“今天的题目是…，轮到你拍了”），把朋友拉进同一主题。

## 2. 三步
### 第一步：主题下发（不需账号）
- 服务器只提供“主题日历”（JSON + 示范图），App 拉取、缓存；离线用缓存。
- 打卡、连续天数、小册、奖励仍在本机（沿用 BookStore，改成多主题，见蓝图 3.7）。
- 不上传任何照片，隐私标签可保持“不收集数据”（拉取日历不含个人信息）。
- 奖励发放：本机记账（现在的 gifted 机制）。风险：改系统时间刷奖励——量小可接受，第二步有账号后再上服务端校验。

### 第二步：社区（Apple 登录）
- 在主题下发：一张 Koco 照片 + 一句话（不超过 80 字）；看他人照片流（按主题、按时间/精选）；点赞；自己的主页 = 自己的小册。
- “只能发 Koco 拍的照片”：只允许从 Koco 自己的拍摄记录（ShotLog）里选，且需当天拍的；不开放相册任意图。
- 审核要求（App Review 1.2）：内容过滤、举报、拉黑、用户协议（EULA 含零容忍条款）、24 小时内处理举报、联系方式。
- 隐私：隐私标签改为收集“用户内容（照片）、标识符（用户 ID）”，用于 App 功能；隐私政策重写；可删号（App Review 5.1.1(v) 要求 App 内删除账号）。
- 地区：大陆以外。大陆用户的 App 里不出现社区入口（按 App Store 地区判断）。

### 第三步：运营
- 每周精选（编辑挑选，被选中送一卷）、合作主题、节日限定胶卷、主题创作者（用户/伙伴出题）。用户主导。

## 3. 技术问题（给 GPT）
1. 后台选型：CloudKit 公共数据库（Apple 登录天然、无服务器、免费额度）vs Supabase/Firebase（运营后台、审核工具、函数）。第一步与第二步分别选什么？迁移成本？
2. 主题日历下发：静态文件（GitHub Pages / CDN）是否足够第一步？如何签名/防篡改？
3. 审核：起步阶段的最小可行审核链路（自动过滤 + 举报队列 + 人工处理），用什么现成服务做图片审核？
4. 奖励防刷：第一步本机记账的可接受风险；第二步如何做服务端校验（交易/兑换码）？送卷用苹果优惠码（Offer Codes）还是 App 内授予？
5. 地区：如何可靠地在大陆隐藏社区（Storefront.current.countryCode？）
6. 时间：v1 之后，第一步和第二步各需多少开发周期（按我们现在的节奏）？

## 4. GPT 讨论后的修订（v0.2，2026-11-23；全文 project/discuss/community-plan.md）
- 私人小册 ≠ 公开发表：放进小册 = 打卡；另有“公开展出”才上传（那时才要 Apple 登录）；只看别人不用登录；奖励不要求公开。
- 打卡时区固定一个，不随出行变；节日主题用明确的全球起止时间。
- 后台：第一步主题日历放对象存储 + CDN，Ed25519 签名、App 内置公钥、缓存数周；第二步 Supabase（Apple 登录 + Postgres + 存储 + 函数，RLS）。CloudKit 公共库要 iCloud 账户，不等于 Apple 登录，且缺运营后台。
- 审核：私有上传 → 自动检测（AWS Rekognition）→ 起步人工确认 → 公开；举报/屏蔽作者有文字标签；删帖、删号、撤销 Apple 授权；去 GPS。
- 奖励：第一步本机记账 + 每日去重 + 时钟倒退检测；第二步服务端账本（每人每日一次、每个里程碑一次），客户端只能申请。赠卷继续走独立权益（不是 StoreKit 购买），登录后可恢复；Offer Codes 留给外部推广。
- 地区：Storefront.current == CHN 时不开放社区（这是“中国大陆商店账户”，不是实际所在地）。
- ShotLog 只是选择范围，不是来源证明；上传时绑定拍摄记录 + 图片摘要，仍不宣称绝对防伪。
- 周期估算（v1 稳定后）：第一步 2–3 周，第二步 6–8 周。
- 界面三件实物（GPT 作图）：相机包里的题签（每日/每周/节日）→ 自己的主题小册（插页、盖章、“公开展出”）→ 大家的主题合订册（Duo 展开左右跨页）。
- 待用户定：每周/节日主题能否投活动期间拍的照片（不补算打卡）；送卷是首次三天一次还是可重复、已拥有全部胶卷的人给什么；7/30 天奖励。

## 5. 用户定的活动规则（2026-11-23）
- 投稿：任何时间拍的都可以，但必须是 Koco 相机拍的，并且符合主题（每日/每周/节日都一样）。
- 连续打卡奖励阶梯：3 天 → 第一卷；7 天 → 一卷；14 天 → 一卷。
- 已拥有全部胶卷的人：达到里程碑时获得一次“新胶卷兑换资格”——以后上新卷时可兑换一卷。
- 以后设计徽章系统、贴纸系统，用来促进活跃度。
- 限定胶卷、限定贴纸、限定徽章：只能通过打卡获得，买不到。

## 6. 界面（2026-11-23/24，用户定方向，GPT 出图）
- 社区在相机包里，和胶卷、维护、小册并列，用左下角收音机波段窗切过去（社区上线时加第四档）。
- 右页 = 只有照片的相册：一张三列透明插页摊在包上，左边一列孔穿在钉在左页的黄铜活页环上；上下滑动看更多；每张夹牛皮纸小签（作者 · 胶卷 · 红心数）。不放横幅（design/community/community_v4.png）。
- 左页 = 轻量导航：推荐 / 关注 / 最新；搜索（人、胶卷、题目）；今日题目小题签当推荐位 + “投一张”；按胶卷看；我的（头像、作品 / 关注 / 获赞、打卡章）。
- 看照片：从插袋抽出放大，下挂信息卡（作者、胶卷、题目、日期、一句话、红心、同款胶卷、··· 举报），“放回”（community_detail.png）。
- 投一张：右页换成自己用 Koco 拍的照片（只从 Koco 拍摄记录里选），选一张、写一句可不填、“放进去”，提示公开（community_post.png）。
- 11/24 用户：看照片要端正地从插袋抽出、有点赞和留言的位置与图标（community_detail_v2.png）；投稿三个入口（题签“投一张”、自己的相册、照片墙上的空插袋）打开同一个自家风格的牛皮纸文件夹浮层，只显示 Koco 拍的照片（系统选图器分不出），投过的盖“已投”（community_post_v2.png）。
